Documentación Técnica del Proyecto: App Odontología / Farmacia

Este documento técnico sirve como referencia completa sobre la arquitectura, almacenamiento y flujos principales de la aplicación Android.

1. Arquitectura General

La aplicación sigue un patrón de diseño que separa las responsabilidades en distintas capas:

  • Vista (Actividades / XML): Interfaz gráfica (LoginActivity, HomeActivity, CartActivity).
  • ViewModel (AuthViewModel): Encargado de la lógica de negocio para la autenticación (registro, login), separando las reglas lógicas de la interfaz gráfica.
  • Repositorios (UserRepository, LocalStorageManager): Manejan la lectura y escritura de la información persistente.
Nota Arquitectónica: No se utiliza una base de datos externa (como Firebase o SQLite/Room) actualmente; en su lugar, se simula una base de datos local robusta usando SharedPreferences y estructuras JSON.

2. Base de Datos Local (LocalStorageManager.kt)

La clase LocalStorageManager es el núcleo de persistencia de datos de la aplicación. Convierte objetos Kotlin a JSON y los almacena localmente en el dispositivo.

2.1 Modelos Principales

Los datos están estructurados en clases (Data Classes):

  • Usuario: Contiene la información del cliente (ID, nombre, correo, contraseña, rol y teléfono).
  • Medicamento: Representa el catálogo (ID, nombre, descripción, precio, stock y URL de imagen).
  • Carrito y DetalleCarrito: Almacenan temporalmente los productos seleccionados antes de la compra.
  • Pedido y DetallePedido: Almacenan el historial de compras confirmadas.
  • Domicilio: Guarda las direcciones del usuario.
  • Domiciliario: Lista de repartidores disponibles (ID, nombre, teléfono, placa, moto).

2.2 Funciones Clave

  • saveUsuario(usuario) / getUsuarioByCorreo(correo): Manejan el registro y lectura de usuarios.
  • saveCarrito(carrito): Actualiza instantáneamente el carrito al añadir productos o modificar cantidades.
  • savePedido(pedido): Mueve los artículos del carrito al historial de compras.

3. Flujo Principal del Usuario

3.1 Autenticación (Login / Registro)

  • RegisterActivity: Realiza validaciones estrictas (correo válido, contraseña > 6 caracteres, campos no nulos). Si es exitoso, delega al AuthViewModel la creación del usuario mediante LocalStorageManager.
  • LoginActivity: Verifica las credenciales. Si coinciden, almacena el logged_in_correo para mantener la sesión abierta y redirige al Home.

3.2 Catálogo (HomeActivity)

  • Se cargan los medicamentos llamando a getMedicamentos().
  • Un RecyclerView con su MedicamentoAdapter pinta la lista en pantalla.
  • Al seleccionar un producto, se crea/actualiza el Carrito en memoria.

3.3 Carrito y Checkout (CartActivity)

  • Modificación de Cantidades: El usuario puede aumentar (+) o disminuir (-) la cantidad. Esto es manejado por el CartAdapter mediante el callback onQuantityChange, lo cual recalcula el total dinámicamente y actualiza la base de datos local al instante.
  • Selección de Domiciliario: Un Spinner carga la lista de repartidores. El usuario debe elegir uno antes de continuar.
  • Procesamiento: Al dar clic en "Confirmar", se crea un objeto Pedido, se vacía el carrito actual, y se reduce el stock de los medicamentos comprados.

3.4 Historial de Órdenes (OrdersActivity)

  • Recupera todos los pedidos cuyo id_usuario coincide con el usuario logueado actualmente.

4.2 Guardar Sesión Activa

// Dentro de LocalStorageManager.kt
fun saveLoggedInUsuario(usuario: Usuario?) {
    if (usuario == null) {
        prefs.edit().remove("logged_in_correo").apply()
    } else {
        prefs.edit().putString("logged_in_correo", usuario.correo).apply()
    }
}
